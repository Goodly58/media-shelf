# Shelf

A fast, filterable catalogue of PC games, books, films and TV series, plus a
personal vocabulary vault. Static site, no backend, no accounts.

**Live:** <https://goodly58.github.io/shelf/>

---

## Deploying

```bash
git push
```

That's the whole deploy. A GitHub Action rebuilds the derived files, validates
the result, and publishes to Pages. If validation fails, **nothing is
published** — the previous site stays up.

There is no separate build step to remember, which is deliberate: two values on
this site are derived, and forgetting either one silently ships a broken site.

| Derived file | Generated by | Breaks if stale |
|---|---|---|
| `assets/stats.json` | `build-stats.js` | Landing page shows the wrong counts |
| `SW_VERSION` in `assets/pwa.js` | `build-version.js` | **Returning visitors keep the old build forever** |
| `movies.html`, `shows.html` | `build-pages.js` | Film/series pages drift from `data/*.json` |

## Checking locally

```bash
node build-pages.js && node build-stats.js && node build-version.js
node validate.js
```

`validate.js` is the same gate CI runs. Every check in it exists because that
exact thing broke once: a duplicated dataset declaration blanking a page, a
stale service-worker cache hiding new builds, a module referenced but not
precached (breaking offline), a class-name collision making text invisible, and
hard-coded counts going stale as the catalogues grew.

## Layout

```
index.html                 landing page
games.html  books.html     hand-maintained catalogues (data is inline)
movies.html shows.html     GENERATED - edit data/*.json, not these files
vocab.html                 vocabulary vault (data lives in the visitor's browser)
data/                      source data for the generated pages
assets/
  site.css / site.js       shared chrome: nav, sign-in, icons, share, shortcuts
  theme.*  motion.*        light/dark theming, animation system
  palette.*  features.*    command palette, compare/export/deep links
  polish.css  a11y.*       visual refinement, accessibility
  sw.js  pwa.js            offline support and install prompt
```

Stylesheets load in a fixed order and the last one wins ties:
`site → theme → palette → features → motion → polish → a11y → theme-patch`.
Adding a new one means adding it to every page **and** to `SHELL` in
`assets/sw.js`, or offline loads will render unstyled. `validate.js` enforces this.

## Adding content

- **Films / series** — edit `data/movies.json` or `data/shows.json`, then push.
  Each row needs `title`, `year`, `genre`, and at least one of
  `metacritic` / `imdb` / `rt`. Missing posters resolve from Wikipedia at runtime.
- **Games / books** — the arrays are inline in the page (`const GAMES = [...]`).

## Caveats worth knowing

- Scores are AI-compiled and approximate, **except** the game scores carrying a
  ✓ badge, which were verified directly against Metacritic.
- After a deploy, GitHub's CDN can serve the old page for a few minutes. If
  something looks wrong immediately after pushing, suspect cache first.
- The theme toggle applies via a page reload. The live in-page swap left the
  body painted in the previous theme, and a correct reload beat a half-repainted
  default theme. Deleting `assets/theme-fix.js` restores the instant transition.
